# Give aiterm quiet chrome and loud content

aiterm should adopt a **native-first, Material 3-grounded language whose identity comes from one rule and one mechanic, not from decoration**. The rule: **monospace means machine text**. Paths, branches, hashes, commands, terminal output and code are set in JetBrains Mono, and everything the app itself says is set in a humanist-engineered sans. The mechanic: **every agent turn, tool call, command and git operation is a "block"** that can be collapsed, copied, re-run, approved or shared. All five platform systems (Apple, Google, Samsung, Microsoft, Meta) agree on content-first restraint, 48dp targets, 4.5:1 contrast, purposeful and interruptible motion, and semantic color roles. Admired tools (Linear, Vercel, GitHub, Raycast, Warp, Things) get their distinctiveness from a deliberately chosen type pairing, a generated role-based palette, hairline-or-tonal structure and one signature interaction tied to the core job. The uncomfortable finding is that **aiterm's current look matches the 2026 "second-order AI slop" cluster almost point for point**: near-black plus one signal accent, mono "template chrome" on every label, uppercase tracked eyebrows, and gray-bordered card stacks. Each of these appears in published catalogues of generated-UI tells. The fix does not mean throwing the identity away. It means making every choice traceable to the product. Keep the teal hue, the near-black lightness, the bottom navigation, the shared sheet frame and the contrast tests. Restrict mono to machine text. Regenerate the palette in OKLCH with accent-tinted neutrals. Replace uppercase labels and bordered stacks with sentence case and tonal grouping. Move spatial motion to springs. Build the block as the signature. A prioritized change list closes the report.

## Five platform systems converge on content-first restraint, and only Android's answer applies

The 2025 platform refreshes went in different visual directions but share one core. **Apple's Liquid Glass** (WWDC25) is a "new translucent material" that reflects and refracts its surroundings and renders specular highlights in real time across iOS 26 and its siblings ([Apple Newsroom](https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/)). Even Apple fences it in. Glass forms "a distinct functional layer for controls and navigation… that floats above the content layer." Apple says "don't use Liquid Glass in the content layer" and "use Liquid Glass effects sparingly" ([HIG: Materials](https://developer.apple.com/design/human-interface-guidelines/materials)). Its motion guidance is the part worth carrying over: "Don't add motion for the sake of adding motion," make motion optional and cancelable, and "generally avoid adding motion to UI interactions that occur frequently" ([HIG: Motion](https://developer.apple.com/design/human-interface-guidelines/motion)). Glass itself should not cross to Android. It is Apple's platform signature. It looks foreign next to Android 16 system UI, and translucency over terminal text costs legibility. Microsoft's Fluent 2 states the governing principle outright: "reuse native platform components and patterns 80% of the time, focusing our energy on signature experiences instead." On mobile it defers to native system fonts and to "iOS and Android guidelines" for shape ([Fluent 2 principles](https://fluent2.microsoft.design/design-principles); [Fluent 2 shapes](https://fluent2.microsoft.design/shapes)).

**Google's M3 Expressive** (May 2025, Android 16) is the native baseline aiterm sits inside. Google calls it "one of our biggest updates in years," built around "more natural, springy animations," emphasized typography and dynamic color ([Google Blog](https://blog.google/products/android/material-3-expressive-android-wearos-launch/)). It is unusually well researched. Google ran **46 studies with more than 18,000 participants**. Expressive designs helped people find key UI elements **up to 4x faster**, and users aged 45+ found elements about as fast as younger users. The same research carries the caveats that matter for a developer tool. Dropping a familiar vertical list hurt usability, removing text labels from actions hurt usability, and "a strong minority preferred calmer designs" ([Google Design research](https://design.google/library/expressive-material-design-google-research)). The lesson is to apply Expressive emphasis to a few key actions, never to everything. Expressive also ships concrete tools aiterm can use. Connected button groups replace deprecated segmented buttons. There are split buttons, a FAB menu, a floating toolbar, and a new loading indicator for waits under about five seconds ([M3 button groups](https://m3.material.io/components/button-groups/overview); [M3 loading indicator](https://m3.material.io/components/loading-indicator/overview)). Flutter has decoupled Material into a `material_ui` package and says "work is already underway on official implementations of Liquid Glass and Material 3 Expressive" ([Flutter blog, Sep 2026](https://flutter.dev/blog/decoupling-material-cupertino)). Until that lands, aiterm should hand-write the Expressive tokens.

**Samsung One UI** matters because so many Android phones are Galaxy devices. Its central layout idea is a split: "a viewing area at the top and an interaction area below," with actionable components grouped into "focus blocks" ([One UI overview](https://developer.samsung.com/one-ui/index.html); [One UI basic layout](https://developer.samsung.com/one-ui/layout/basic.html)). Samsung rations depth effects: "These effects shouldn't be used excessively," and "Avoid applying the dim effect and shadow effect at the same time" ([One UI visual depth](https://developer.samsung.com/one-ui/structure/visual-depth.html)). It asks for side margins of at least 24dp near curved edges ([One UI grid](https://developer.samsung.com/one-ui/layout/grid.html)). Its color rule is "calm colors… in large areas… bright and distinctive colors… for small areas" ([One UI color](https://developer.samsung.com/one-ui/color/system.html)). One UI 7's circles and pale gradients are Samsung's system identity, not guidance for third-party apps.

**Fluent 2** contributes the "built for focus" posture: "Less visual clutter and noise keeps people centered, calm, and confident." It also adds explicit rules aiterm currently breaks. Use sentence case and avoid all caps ([Fluent typography](https://fluent2.microsoft.design/typography)). "Avoid overusing brand colors or using them on large surfaces," and semantic red/yellow/green are not for decoration ([Fluent color](https://fluent2.microsoft.design/color)). Top-level navigation should "use a quick fade transition instead of moving or sliding UI elements" ([Fluent motion](https://fluent2.microsoft.design/motion)). **Meta** publishes no mobile component system, only content-design and accessibility doctrine. Language should be "simple, straightforward and human," terminology should stay consistent across surfaces ([Design at Meta](https://www.meta.com/design-at-meta/blog/writing-the-metaverse/)), and "nearly 30 percent of accessibility issues can be remediated through upholding design system standards" ([Design at Meta: accessibility](https://www.meta.com/design-at-meta/blog/accessibility-and-design-systems/)).

The published numbers cluster tightly, so aiterm can adopt them as hard floors:

The systems genuinely disagree on corner radii (Fluent 4–12, Material up to 48), on dialog placement (Samsung puts choice dialogs at the bottom), and on depth (glass, blur/dim, tonal, shadow). On Android, take Material's answer and temper it with Fluent's calm.

## Admired apps win with one constraint and one signature mechanic

The apps developers admire do not share a look. They share a method. **Type is chosen or commissioned on purpose.** Anthropic's agency paired Styrene with Tiempos to be "technically refined and charmingly quirky" in "a category full of tech clichés," and claude.ai now ships in-house Anthropic Sans and Serif ([Geist studio: Anthropic](https://geist.co/work/anthropic); [claude.ai CSS](https://assets-proxy.anthropic.com/claude-ai/v1/_next/static/css/026d87fb2c6610cf.css)). Vercel built Geist **mono-first**: "We began by creating a monospace version that prioritized readability… in coding environments" ([vercel.com/font](https://vercel.com/font)). GitHub's Mona Sans has three variable axes, with Hubot Sans reserved for headers ([GitHub Blog](https://github.blog/news-insights/company-news/introducing-mona-sans-and-hubot-sans/)). Linear keeps Inter for body and uses Inter Display "to add more expression to our headings" ([Linear redesign](https://linear.app/now/how-we-redesigned-the-linear-ui)). Peer editors make the same split: Zed defaults to IBM Plex Sans for UI and Lilex for the buffer ([Zed defaults](https://github.com/zed-industries/zed/blob/main/assets/settings/default.json)). The pattern is **one sans voice for the interface and one mono voice for code**, with any expressive third face confined to display sizes.

**Color is generated and role-assigned, never hand-picked.** Linear moved theme generation to LCH because it is perceptually uniform, and replaced 98 variables per theme with three inputs: base, accent and contrast. It then deliberately reduced how much blue fed the neutrals, for "a more neutral and timeless appearance" ([Linear redesign](https://linear.app/now/how-we-redesigned-the-linear-ui)). Vercel's Geist gives every step a job: 100–300 backgrounds, 400–600 borders, 700–800 solids, 900 secondary text, 1000 primary text. It has only two backgrounds, and the second is used "sparingly" ([Geist colors](https://vercel.com/geist/colors)). GitHub's Primer inverts neutral scales between modes so functional tokens such as `fgColor-*` and `bgColor-*` stay shared, and its high-contrast themes target 7:1 ([Primer color](https://primer.style/foundations/color/overview)). What separates the apps visually is **neutral temperature**. Linear's March 2026 refresh swapped cool blue-grays for "a warmer, less saturated gray that still feels crisp," and warned that too warm looks "muddy" ([Linear: calmer interface](https://linear.app/now/behind-the-latest-design-refresh)).

**Craft shows in alignment, density control and one mechanic tied to the core job.** Linear aligned every icon and label, which users "feel after a few minutes of using the app." Raycast enlarged the search bar because "almost every interaction goes through it," redrew icons under one stroke-and-radius rule, and turned a hidden ⌘K menu into a visible bottom action bar that shows shortcuts beside actions "so users can learn them over time" ([Raycast redesign](https://raycast.com/blog/a-fresh-look-and-feel)). Things 3 has the draggable Magic Plus, cards that expand in place, and haptics on pickup ([MacStories](https://www.macstories.net/reviews/things-3-beauty-and-delight-in-a-task-manager/)). Warp's defining move is structural: "Commands and their output are visually grouped into blocks," with a 60fps target even on huge displays ([Warp: How Warp Works](https://warp.dev/blog/how-warp-works)). Arc's distinctiveness came from moving tabs to a sidebar and adding Spaces, not from its gradients ([Arc design study](https://blakecrosley.com/guides/design/arc)). Notion stood apart with Roman Muradov's hand-drawn ink illustrations and the principle "Show, don't tell" ([Notion blog](https://www.notion.com/blog/the-thinking-behind-our-latest-brand-campaign)). On mobile, GitHub follows an 8pt grid but leaves component sizing to iOS and Android ([Primer mobile](https://primer.style/native/mobile/foundations)).

What aiterm should **not** copy is just as clear. Claude's cream, clay and serif would make aiterm look like a Claude skin while it hosts Codex and Gemini too, and the "Claude clay" hex values on extraction sites conflict with each other (#D97757, #CC785C, #CD6F47, #C15F3C), so none of them is official ([webdesignhot](https://www.webdesignhot.com/design.md/claude-ai/); [studiosiraj](https://studiosiraj.com/blog/anthropic-brand-identity-case-study)). Vercel's stark black-and-white and the Geist font now read as the Next.js/shadcn default. Arc's frosted glass and big gradients hurt legibility over terminal text and break platform consistency on Android. Linear's ultra-dense desktop chrome and Raycast's keyboard hints do not translate literally to 48dp touch. Translate them into an action bar, long-press menus and visible gesture hints instead.

## Generated UI is a stack of unexamined defaults

The practitioner literature agrees on how to build hierarchy, and that order of tools is the strongest remedy against a generated look. Refactoring UI says to build hierarchy with weight and color, to "use fewer borders," and to "add spacing instead of spacer lines" ([Refactoring UI summary](https://alexanderweichart.de/5_Archive/3_Resources/Library/Refactoring-UI/Refactoring-UI-design-principles)). Linear's 2026 refresh condensed this into "Don't compete for attention you haven't earned" and "Structure should be felt not seen." It dimmed the sidebar, cut and softened separators, removed colored icon backgrounds, and judged success by the test "If most people don't immediately notice what changed, that's probably a good sign" ([Linear: calmer interface](https://linear.app/now/behind-the-latest-design-refresh)). Vercel's guidelines, co-authored by Rauno Freiberg, add checkable detail rules. Child radii are concentric with their parent. Borders and shadows on tinted surfaces are tinted toward the same hue. Interactive states have more contrast than the resting state. Status never relies on color alone. Numbers that change use tabular figures. Every element aligns to a grid, baseline, edge or optical center ([Vercel guidelines](https://vercel.com/design/guidelines)). The counterweight comes from NN/g. In a 71-person eye-tracking study, weak-signifier flat designs took **22% more time** and drew **25% more fixations** ([NN/g flat UI](https://www.nngroup.com/articles/flat-ui-less-attention-cause-uncertainty/)). Static grouping can be borderless, but tappable things must still look tappable.

Crafted motion follows the same restraint. Emil Kowalski says animations "should also usually be shorter than 300ms," should prefer ease-out, and must be interruptible ([Emil Kowalski](https://emilkowal.ski/ui/great-animations)). Rauno removes animation from high-frequency actions because it becomes "cognitive burden after seeing the same animation for the hundredth time." He keeps gesture momentum on release, launches expanded views from their source, and commits destructive gestures only on release ([rauno.me](https://rauno.me/craft/interaction-design)). Josh Comeau notes that springs are "often not bouncy at all" and uses them for movement, not color ([Josh Comeau](https://www.joshwcomeau.com/animation/a-friendly-introduction-to-spring-physics/)). Apple's WWDC23 spring guidance calls bounce 0 "the most versatile" and warns that bounce above about 0.4 "may feel too exaggerated for a UI element" ([WWDC23 10158](https://developer.apple.com/videos/play/wwdc2023/10158/)).

The 2025–2026 tell catalogues share one diagnosis: **slop is the statistical average chosen without reason**. First-order tells include purple-indigo gradients, Inter for every word, `rounded-2xl` plus `shadow-lg` plus `backdrop-blur` on everything, the sparkle icon for AI, and the same fade-up on every element. A second-order "tasteful" layer is now recognized as well: cream plus terracotta, near-black plus one acid accent, "all-caps tracked eyebrow labels and mono 'template chrome'," `A · B · C` meta strings, decorative 01/02/03 numbering and an emerald fallback color ([avoid-ai-design](https://github.com/funboy322/avoid-ai-design)). Anthropic's own frontend-design skill lists "using all caps for labels," "adding unnecessary typographic labels above content," tinted near-black "standing in for black," "the SaaS-card kit: content chopped into identical rounded cards," and "the same soft grey shadow." Its remedies are to choose typefaces deliberately, draw the palette from the subject's "materials and vernacular," and "spend your boldness in one place" ([Anthropic frontend-design SKILL.md](https://raw.githubusercontent.com/anthropics/claude-code/main/plugins/frontend-design/skills/frontend-design/SKILL.md)). Kosta Canatselis adds "uniform everything" and missing empty, loading and error states, because generators "nail the happy path." He also names the one-sided colored left border on panels ([Mania Design](https://www.mania.design/blog/spot-the-slop-a-ui-designers-guide-to-fixing-ai-defaults/)). These catalogues are designer opinion, not user research. No study yet shows that laypeople penalize the tells. The underlying test still holds: "would you have made it for any similar page?" ([avoid-ai-design](https://github.com/funboy322/avoid-ai-design)).

| Tell | Present in aiterm today? | Remedy for aiterm |
|---|---|---|
| Mono as "template chrome" on all text | Yes: JetBrains Mono everywhere | Mono only for machine text; sans for the app's own voice |
| All-caps tracked eyebrow labels | Yes | Sentence-case titleSmall headers, or no label where spacing already groups |
| Near-black plus one signal accent | Yes: #0E0F12 plus teal | Keep, but derive neutrals from the accent hue and ration the accent to defined roles |
| Gray-bordered card kit, cards in cards | Yes: bordered cards | Tonal grouping plus spacing; hairlines only with a job |
| Emerald fallback / one hue as two | Risk: teal accent vs git-added green | Separate accent hue (172°) from add/success hue (142°), always paired with +/− glyphs |
| Sparkle for AI | Avoid | Name the agent in text; status glyphs show state |
| One-sided colored borders | Avoid on blocks | Status glyph plus label in the block header |
| Same entrance motion everywhere | Check | No entrance motion; animate only what changed |
| Missing unhappy paths | Check | Designed empty, loading, error and offline states for every screen |

## Zero friction on a phone means central, visible and reversible

The popular "put everything at the bottom" thumb-zone advice overstates the evidence. Steven Hoober's field study of 1,333 observations found grips change constantly: **49% one-handed, 36% cradled, 15% two-handed**. He later withdrew his coarse reach drawings and said people touch the **center** of the screen more, faster and more accurately ([UXmatters 2013](https://www.uxmatters.com/mt/archives/2013/02/how-do-users-really-hold-mobile-devices.php)). Touch accuracy is about **7mm at the center versus 12mm at the corners**. His placement rule puts primary actions and content in the middle half to two-thirds, a few secondary actions on the top and bottom edges, and tertiary functions behind a corner menu. It keeps unrecoverable actions away from frequently used controls, asks for list rows **at least 9–10mm tall** with the whole row tappable, and recommends designing everything about 20% larger ([UXmatters 2017](https://www.uxmatters.com/mt/archives/2017/07/design-for-fingers-touch-and-people-part-3.php)). NN/g calls reachability a "largely incorrect" rationale for bottom sheets ([NN/g bottom sheets](https://www.nngroup.com/articles/bottom-sheet/)). For aiterm, the terminal, diff or conversation owns the center. The input bar and extra-keys row form the one bottom strip, which is reachable because it sits beside the keyboard. Kill session, force push and discard all live in overflow menus, never next to Send or Enter. Note that 48dp is only about 7.6mm (my conversion at 160dp per inch), so Hoober's 9–10mm points to roughly 56–64dp rows for comfortable density.

Visible beats hidden. On mobile, visible navigation was used **89% of the time versus 44%** for hidden navigation, and found sooner (24s vs 33s) ([NN/g](https://www.nngroup.com/articles/find-navigation-mobile-even-hamburger/)). Engagement "plummeted" when Polar and Zeebox hid navigation and rose when Facebook moved to a visible tab bar ([LukeW](https://www.lukew.com/ff/entry.asp?1945)). Hoober rejects "secret interactions" and argues for "boring interfaces" ([UXmatters 2017](https://www.uxmatters.com/mt/archives/2017/07/design-for-fingers-touch-and-people-part-3.php)). Gestures are therefore accelerators layered on visible controls. Working Copy is the model here: tap a file to stage it, long-tap or swipe to stage a hunk, swipe left as a commit shortcut, and keep a visible Commit button as the primary route ([Working Copy manual](https://workingcopyapp.com/manual/commit-revert/)). Termux shows the extra-keys pattern: a configurable row with ESC, TAB, CTRL, ALT and arrows, plus swipe-up popups for secondary characters or macros ([Termux man page](https://gitea.dmz.rs/disu1950/man2html/raw/branch/main/termux-man.html)). Blink keeps Ctrl and Alt sticky "like in a real keyboard" ([Blink](https://github.com/blinksh/blink)). aiterm should print each popup's secondary character on the key so the gesture is never hidden-only. It should also avoid edge-swipe session switching, which collides with Android's back gesture and fails on curved or cased phones ([UXmatters 2017](https://www.uxmatters.com/mt/archives/2017/07/design-for-fingers-touch-and-people-part-3.php)).

Sheets, dialogs and screens each have a job. NN/g's rule: use a sheet for quick tasks where the background context helps, never for long or complex content, and never "to replace typical page-to-page user flows." Always provide "a clear Close button" plus system Back, because the grab handle "is easy to ignore." Never stack sheets, because Back and X end up dismissing different levels ([NN/g bottom sheets](https://www.nngroup.com/articles/bottom-sheet/)). Apple agrees: "Display only one sheet at a time" ([HIG sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)). M3 caps sheet width at 640dp ([MDC BottomSheet](https://github.com/material-components/material-components-android/blob/master/docs/components/BottomSheet.md)). The resulting rule for aiterm: use a sheet for the branch picker, quick actions on a file, session or commit, the new terminal/agent chooser, and tool-call details. Use a full screen for diff review, the file browser, history, multi-section settings, SSH keys and authenticated clone. Use a dialog only for irreversible remote operations.

Feedback should be inline, persistent when action is needed, and undoable when possible. Generic "Are you sure?" prompts get clicked through by habit. A confirmation must restate the specific request and its consequence ([NN/g confirmation](https://www.nngroup.com/articles/confirmation-dialog/)), and reversible actions should act immediately with Undo ([NN/g accelerators](https://www.nngroup.com/articles/ui-accelerators/)). Toasts suit passive notices but fail for errors. In one NN/g test a user missed an error toast and waited five minutes. Action-required notifications "should be intrusive" and persist ([NN/g indicators](https://www.nngroup.com/articles/indicators-validations-notifications/)). For loading: show nothing under about 1 second, a skeleton for full-page loads under 10 seconds, a spinner for a single module, and a progress bar with an estimate beyond 10 seconds ([NN/g skeletons](https://nngroup.com/articles/skeleton-screens/)). Long agent runs need ambient OS status. GitHub Mobile ships Android live-update notifications for Copilot CLI sessions with four states (**in progress, waiting for user input, idle, finished**) and an opt-out button in the first notification ([GitHub changelog](https://github.blog/changelog/2026-07-08-github-mobile-live-notifications-for-copilot-cli-sessions/)). Claude Code now pushes "when a long task finishes or Claude needs your input" ([ClaudeDevs](https://x.com/ClaudeDevs/status/2049154855143649315)). Replit notifies when Agent needs help or is done ([Replit docs](https://docs.replit.com/platforms/mobile-app)). aiterm runs agents locally, so the foreground-service notification it already needs can carry these four states and deep-link straight to a pending approval.

## The aiterm design language: principles, tokens and component rules

### Six principles

**Native first, signature second.** Use Material 3 components and Android conventions (predictive back, edge-to-edge, the system font scale, labeled navigation) by default, following Fluent's 80% rule. Spend custom effort only on the block, the terminal and the agent surfaces. **Mono means machine.** A user should be able to tell, without reading, whether text is the app talking or something literal they could copy into a shell. **Quiet chrome, loud content.** Navigation, headers and metadata recede (muted text, smaller icons, no fills), so the terminal, diff and agent output carry the contrast. **Structure by space, then tone, then line.** Group with proximity first, then one surface-tone step, and use a hairline only when it has a job. **Visible first, gestures second, reversible always.** Every gesture has a visible twin. Every reversible action gets Undo instead of a dialog. **Motion explains, never decorates.** Animate only what changed. Repeated actions get no animation. Gestures keep their velocity. Reduced motion always works.

### Typography: a sans voice for the app, JetBrains Mono for the machine

Pair **IBM Plex Sans** (UI) with **JetBrains Mono** (machine text). Both are SIL OFL 1.1 and can be bundled unmodified ([IBM Plex license](https://github.com/IBM/plex/blob/master/LICENSE.txt); [JetBrains Mono license](https://github.com/JetBrains/JetBrainsMono/blob/master/OFL.txt)). Ship the licenses through `LicenseRegistry`. Plex Sans has engineered character without sitting on any tell list, unlike Inter, Geist, Space Grotesk and Instrument Serif ([avoid-ai-design](https://github.com/funboy322/avoid-ai-design)). It carries no Vercel or GitHub brand association, and a respected editor already uses it for UI ([Zed](https://github.com/zed-industries/zed/blob/main/assets/settings/default.json)). JetBrains Mono stays because it is already aiterm's voice, has Nerd Font builds, and is what Ghostty embeds ([Ghostty fonts](https://github.com/ghostty-org/ghostty/tree/main/src/font/res)). Avoid Berkeley Mono: its app license bans use in terminals and editors ([usgraphics FX-700](https://usgraphics.com/catalog/FX-700)). The x-height match between Plex Sans and JetBrains Mono is unverified. Test inline mixing at 14sp. If Plex feels too wide in dense rows, fall back to Inter with tabular figures and Inter Display at 20sp and up, and accept that it is the more generic choice. Use no serif. A serif "AI voice" is Claude's signature ([aichatdaily](https://www.aichatdaily.com/ai-analysis/ai-companies-pivot-serif-fonts-look-more-human)), and in aiterm the sans/mono split already separates the agent's prose from machine output.

The ramp is M3's, so every line height is a multiple of 4 ([TypeScaleTokens.kt](https://github.com/androidx/androidx/blob/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens/TypeScaleTokens.kt)). Terminal leading follows Zed's 1.3 "standard" ([Zed](https://github.com/zed-industries/zed/blob/main/assets/settings/default.json)). Use only 400, 500 and 600 (Apple warns against light weights ([HIG typography](https://developer.apple.com/design/human-interface-guidelines/typography))). Keep tracking at 0 and never letter-space for decoration. Apply `FontFeature.tabularFigures()` to timers, token counts, file sizes and diff stats ([Vercel guidelines](https://vercel.com/design/guidelines)). Use proper "…" and curly quotes in UI copy. Mono gets straight quotes, because they are literal.

### Color: an OKLCH generator with three inputs and roles for every step

Copy Linear's model. Three inputs produce everything: **accent hue 172°** (aiterm's existing teal), **neutral tint** (the same hue family at 190°, chroma ≤0.012), and **contrast level**. Every output step has a Radix/Geist-style job ([Radix scale](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale); [Geist colors](https://vercel.com/geist/colors)). The neutrals become a faint **"phosphor graphite"**: a near-black tinted toward the accent instead of the cool 271° blue-violet aiterm uses now. Tinting the neutrals toward the accent applies Vercel's hue-consistency rule and Linear's base-plus-accent derivation, and it avoids both the cool slate default and the warm Claude/Warp/Linear trend. Dark lightness starts at L 16.5%, inside the 13–18% band of Radix, M3 and Tailwind, and never at #000 ([design tokens: Radix/M3/Tailwind](https://unpkg.com/@radix-ui/colors@3.0.0/slate-dark.css); [material-color-utilities](https://github.com/material-foundation/material-color-utilities/blob/main/typescript/dynamiccolor/color_spec_2021.ts)). Success and diff-added sit 30° away at 142° with higher chroma. Follow the system light/dark setting by default ([HIG dark mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode)). Offer three opt-ins: "Match wallpaper" dynamic color for chrome on Android 12+ ([Android M3](https://developer.android.com/develop/ui/compose/designsystems/material3)), an AMOLED-black terminal, and "Terminal always dark" for light-theme users.

### Space, shape, elevation and icons

**Spacing** uses a 4dp base with steps of 2 (icon nudges only), 4, 8, 12, 16, 20, 24, 32, 40 and 48, which is compatible with Fluent's ramp and M3 line heights ([Fluent layout](https://fluent2.microsoft.design/layout)). The screen gutter is 16dp for text. Row backgrounds may bleed to the edge, but text never comes closer than 16dp, and 24dp is used for prose and empty states, per Samsung's curved-edge minimum ([One UI grid](https://developer.samsung.com/one-ui/layout/grid.html)). Comfortable density uses 56dp single-line and 72dp two-line rows, closing in on Hoober's 9–10mm. A **Compact** setting (Raycast's Compact Mode precedent ([Raycast](https://raycast.com/blog/a-fresh-look-and-feel))) drops rows to 48dp and 64dp and never shrinks hit areas below 48dp.

**Radii** are cut to four values plus full, all drawn from M3's token set ([ShapeTokens.kt](https://github.com/androidx/androidx/blob/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens/ShapeTokens.kt)). Use **4** for checkboxes, inline code chips and diff hunks. Use **8** for buttons, inputs, chips and the selected-row highlight. Use **12** for cards, blocks, the terminal pane, menus and snackbars. Use **20** (LargeIncreased) for sheet top corners and dialogs. Use **full** for the navigation indicator, status dots and the FAB. Choosing 20 over M3's 28 for sheets and dialogs is a deliberate step toward Fluent's tighter 12 for a precision tool. Nest radii concentrically: a 12dp block with a 4dp inset holds 8dp controls ([Vercel guidelines](https://vercel.com/design/guidelines)).

**Elevation is tone, not shadow** ([Android M3](https://developer.android.com/develop/ui/compose/designsystems/material3)). Level 0 is bg, level 1 surface, level 2 container, level 3 containerHigh, and level 4 overlay. Modal sheets and dialogs use a scrim (black at 50% in dark, 32% in light) and **no shadow**, because Samsung forbids dim plus shadow ([One UI visual depth](https://developer.samsung.com/one-ui/structure/visual-depth.html)). Non-modal menus and popovers get a borderSubtle hairline in dark mode. In light mode they get one two-layer soft shadow (ambient plus key), as Vercel recommends ([Vercel guidelines](https://vercel.com/design/guidelines)). The app uses no blur, no glass and no gradients. The top app bar gains a borderSubtle bottom hairline only while content is scrolled beneath it, which is the Android-native version of Apple's scroll-edge effect ([HIG layout](https://developer.apple.com/design/human-interface-guidelines/layout)).

**Icons** switch to **Material Symbols Outlined** through `material_symbols_icons` (updated July 2026). The older Material Icons set is "no longer updated" ([material-design-icons](https://github.com/google/material-design-icons); [pub.dev](https://pub.dev/packages/material_symbols_icons)). Drive Flutter's variable axes ([icon.dart](https://github.com/flutter/flutter/blob/master/packages/flutter/lib/src/widgets/icon.dart)): weight 400, optical size 20 at 20dp and 24 in navigation, grade −25 on dark surfaces, and fill animating from 0 to 1 for the selected destination. Use one set only and never mix in another library, following Raycast's one-stroke rule. Never use a sparkle for AI. Identify each agent by name ("Claude Code", "Codex", "Gemini CLI") in the block header, and show state with status glyphs: a running dot in accent, an amber "needs input" mark, a check in success color for done, an × in danger color for failed. Always pair the glyph with a text label.

### Motion: springs for space, short tweens for effects, nothing for repetition

The springs come straight from M3's standard scheme. Perceptual durations are my calculation with Flutter's and Apple's `duration = 2π/√stiffness` model ([StandardMotionTokens.kt](https://github.com/androidx/androidx/blob/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens/StandardMotionTokens.kt); [spring_simulation.dart](https://github.com/flutter/flutter/blob/master/packages/flutter/lib/src/physics/spring_simulation.dart)). Build them with `SpringDescription.withDampingRatio(mass: 1, …)` and drive them with `animateWith(SpringSimulation(...))` so a fling's velocity carries into the settle.

| Token | Spec | ≈ Duration / bounce | Use |
|---|---|---|---|
| spatialFast | ζ 0.9, k 1400 | 168ms / 0.1 | Chip and toggle movement, small expand |
| spatialDefault | ζ 0.9, k 700 | 237ms / 0.1 | Block expand and collapse, sheet snap, row reorder |
| spatialSlow | ζ 0.9, k 300 | 363ms / 0.1 | Container transform from row to full screen |
| expressive | ζ 0.8, k 380 | 322ms / 0.2 | Two moments only: FAB menu open, agent "done" check |
| effectsFast | ζ 1.0, k 3800 (or 100ms tween) | 102ms / 0 | Pressed and selected color changes |
| effectsDefault | ζ 1.0, k 1600 (or 150ms `Easing.standard`) | 157ms / 0 | Fades, crossfades, theme interpolation |
| topLevelSwitch | 150ms fade, no slide | n/a | Bottom-nav destination change ([Fluent motion](https://fluent2.microsoft.design/motion)) |
| none | 0 | n/a | Keystrokes, terminal output, message send, extra keys, menu open from long-press |

Expressive fast spatial (ζ 0.6, bounce about 0.4) sits at Apple's "too exaggerated" edge ([WWDC23](https://developer.apple.com/videos/play/wwdc2023/10158/)), so it is excluded. When `MediaQuery.disableAnimationsOf(context)` is true, every spatial token becomes an instant change or a fade of 100ms or less ([media_query.dart](https://github.com/flutter/flutter/blob/master/packages/flutter/lib/src/widgets/media_query.dart)). Animate only transform and opacity, launch expanded views from their source row, and keep every animation interruptible ([Vercel guidelines](https://vercel.com/design/guidelines); [rauno.me](https://rauno.me/craft/interaction-design)). aiterm's current 120ms and 220ms cubic tweens fall within these durations. Keep them for effects and move spatial motion to springs.

### Haptics: native constants, scaled to frequency and importance

*As built: see "Haptics, as built" under [What we learned and applied](#what-we-learned-and-applied).*

Android's rules are "less is more," "favor rich and clear haptics over buzzy haptics," predefined `HapticFeedbackConstants` before anything custom, and "given the choice of buzzy haptics or no haptics… choose no haptics" ([Android haptics principles](https://developer.android.com/develop/ui/views/haptics/haptics-principles)). Flutter's `HapticFeedback` covers only part of the constant set ([haptic_feedback.dart](https://github.com/flutter/flutter/blob/master/packages/flutter/lib/src/services/haptic_feedback.dart)). Add one `MethodChannel('aiterm/haptics')` that calls `View.performHapticFeedback` with an API-level fallback table, so user settings always apply ([HapticFeedbackConstants](https://developer.android.com/reference/android/view/HapticFeedbackConstants)).

| Interaction | Constant (API) | Flutter fallback |
|---|---|---|
| Extra-keys row key | KEYBOARD_TAP (8), or KEYBOARD_PRESS/RELEASE (27) | `mediumImpact()` |
| Sticky modifier latch / unlatch | TOGGLE_ON / TOGGLE_OFF (34) | `selectionClick()` |
| Long-press menu on block, row or file | LONG_PRESS (3) | `vibrate()` |
| User-started command or agent run succeeds; commit or push done | CONFIRM (30) | `successNotification()` |
| Push rejected, command failed, approval denied | REJECT (30) | `errorNotification()` |
| Button group or picker selection, tab swipe | SEGMENT_TICK (34) | `selectionClick()` |
| Font-size slider, scrollback scrubber | SEGMENT_FREQUENT_TICK (34) | none |
| Swipe-to-stage or pull-to-refresh threshold | GESTURE_THRESHOLD_ACTIVATE / DEACTIVATE (34) | `selectionClick()` |
| Pick up a project, tab or file to reorder | DRAG_START (34) | `vibrate()` |
| Streaming tokens, terminal output, scroll | none | none |

### Microcopy rules

Write in sentence case everywhere: "New session", "Clone repo". Fluent and Google's style guide both reject all caps ([Fluent typography](https://fluent2.microsoft.design/typography); [Google style: UI elements](https://developers.google.com/style/ui-elements)). Buttons start with a verb and name the outcome: "Commit 3 files", "Push to origin", "Run again", "Delete project". Never use "OK", "Yes" or "Get started" on a consequential action. "Get started" and "Seamless/Powerful" copy are named tells ([avoid-ai-design](https://github.com/funboy322/avoid-ai-design)). Errors answer "what went wrong?" and "how do I fix it?" and include the literal value in mono: "Couldn't reach `github.com`. Check your connection and try again." Use no exclamation marks and no blame ([Google: error messages](https://developers.google.com/tech-writing/error-messages)). Every icon-only button has a tooltip and a semantics label ([Google style](https://developers.google.com/style/ui-elements)). Use one term per concept across the app (Meta's consistency rule ([Design at Meta](https://www.meta.com/design-at-meta/blog/writing-the-metaverse/))): pick "session" or "terminal", and "agent" or "assistant", and never alternate. Leave out labels that only restate what spacing already shows, and avoid `A · B · C` meta strings. Write "main, 3 ahead" as structured metadata with a glyph instead.

| P2-13 | Compact density setting; "Match wallpaper", AMOLED terminal and "Terminal always dark" options; M3 Expressive button groups, split button and loading indicator as Flutter's `material_ui` lands | Power-user comfort and native alignment | Medium |
| P2-14 | Write the language into a DESIGN.md beside `theme.dart` and add CI golden and contrast tests for both themes at 100% and 200% text | Prevents drift; fits CI-only widget testing | Low |

### Status (October 2026)

- **Done:** P0-1 to P0-5, P1-6, P1-8 to P1-11, P2-12 to P2-14.
- **Icons (P2-12):** Material Symbols Outlined is subset to the app's icons by `tool/icons/generate.py`, which writes `assets/fonts/MaterialSymbolsOutlined.ttf` (about 100 KB, all four axes) and `lib/app/icons.dart`. To add an icon, list it in `tool/icons/icons.txt` and run the script; the full package would ship 30 MB of fonts in debug builds, which don't tree-shake. Fill is reserved for state: the selected tab (animated), success checks, a pinned tab and folders. Agents use `robot_2`, never a sparkle.
- **Options (P2-13):** Theme (System, Light or Dark; System is the default), Wallpaper colors (Android 12+; the wallpaper hue at the teal's tones, so contrast holds for every hue), Compact lists (48/64dp rows; hit areas stay at 48dp), and for the terminal Always dark and Black background. M3 Expressive components wait for Flutter.
- **Tests (P2-14):** Contrast tests cover both themes, wallpaper accents across every 15° of hue, and the black terminal. Widget tests lay out the main screens at 200% text on a 360dp phone, in dark and in light with compact lists, and fail on any overflow. These tests are layout checks, not pixel goldens: CI is the only runner, so goldens would mostly catch rendering noise.
- **High contrast:** a switch in Appearance. Text and status colors reach 7:1 (AAA), control outlines 4.5:1, and groups and cards get a visible edge. Wallpaper accents use higher-contrast tones too. `test/contrast_test.dart` enforces all of it.
- **Blocks (P1-7):** optional, and off by default: the agents' own terminal UIs stay the default. Settings has an Agent settings group with Blocks, a switch per agent, and Show thinking.
  - **Protocol:** blocks use the [Agent Client Protocol](https://agentclientprotocol.com) rather than scraping terminal output. Gemini CLI speaks it natively (`gemini --acp`). Claude Code and Codex use the official adapters (`@agentclientprotocol/claude-agent-acp`, `@agentclientprotocol/codex-acp`), installed on first use with `--omit=optional` and pointed at the agents already installed (`CLAUDE_CODE_EXECUTABLE`, `CODEX_PATH`). That keeps one copy of each agent and one sign-in.
  - **Client:** `lib/agents/acp/` holds the client: JSON-RPC over newline-delimited stdio. It claims no file or terminal capability, so agents use their own tools.
  - **What renders:** messages (Markdown), thinking, tool calls (status glyph, kind icon, mono command or path, diffs with + and − marks), plans, and permission requests pinned above the message box.
  - **Controls:** the agent's mode sits in the chat bar, and its model is in the menu; the last choice of each is remembered per agent. "/" lists the agent's commands.
  - **Sessions:** sessions resume after a restart when the agent supports `session/load`.
  - **Workspace:** when a project has both blocks and terminals, the Agent tab switches between them, and both stay running. Sign-in still happens in the agent's own UI ("Sign in" opens it).
- **Open:** blocks for plain shell commands (OSC 133 marks) are not built.

### Identity: look like a tool, not like generated UI

### Type, color and contrast

### Haptics, as built

Android: "less is more"; clear clicks, never buzzy ("given the choice of buzzy or none, choose none"); predefined constants; strength follows importance; in sync with what's on screen. One UI: distinct patterns per event, with two quick pulses for an error, and avoiding overstimulation. Latency studies: within 30–50 ms of the visual reads as instant. Sources: [Android haptics principles](https://developer.android.com/develop/ui/views/haptics/haptics-principles), [One UI haptics](https://developer.samsung.com/one-ui/sound-and-haptic/haptic.html), [Immersion: haptic latency](https://www.immersion.com/wp-content/uploads/2015/10/ux-impact_haptic-latency-in-auto_jul13v1.pdf).

| Moment | Haptic | Why |
|---|---|---|
| A switch flipped | TOGGLE_ON / TOGGLE_OFF | The system's own pattern for switches |
| Send, pick a mode, open a block, attachments added, a "/" command picked | A tick | A small confirmation of a choice |
| The agent asks permission | Attention (a firm click) | The one moment that needs you |
| A turn finishes / allowed / committed | CONFIRM | Something finished well |
| A turn fails / rejected | REJECT | Failure, felt differently from success |
| A long press opens a menu | LONG_PRESS | Platform convention |
| Streaming text, terminal output, scrolling, typing, your own Stop | None | Too frequent, or you already got a tick |

Rules: haptics fire only while that screen is visible and the app is in front. They use `View.performHapticFeedback`, so Android's own setting applies, and **Settings → Haptic feedback** turns them off.

### Engineering lessons that shaped the experience

| Learned | Applied |
|---|---|
| Debug builds don't tree-shake icon fonts; the full Material Symbols set would add about 30 MB | `tool/icons/generate.py` subsets the variable font to the app's icons (about 100 KB) and generates `AppIcons` |
| `gh auth login` is reliable without a terminal; scraping its prompts wasn't | Sign-in runs on plain pipes and reads the code and URL |

| A corrupted NDK download once failed a build | The NDK installs up front, with retries |

## Conclusion

The research points somewhere unexpected. aiterm's risk is not looking unpolished. It is looking polished the way generated software looks polished: a near-black screen, one tasteful accent, mono everywhere, small caps and outlined boxes. The way out is not a louder aesthetic. It is to tie each visual choice to a fact about the product. Mono marks literal text. The accent marks the one thing you can do or the agent that is working. Tone marks depth. A block marks a unit of work that can be inspected, repeated or undone. That makes aiterm distinctive in the way Warp's blocks and Raycast's action bar are distinctive: through structure that only this product needs, carried by an otherwise native, quiet Android surface.

Two uncertainties remain. The catalogue of AI tells is designer consensus, not user research, so the payoff of these changes should be judged by task speed and error rate (time to approve, time to stage and commit, missed failures) rather than by taste. The Plex Sans and JetBrains Mono pairing also needs an on-device inline-mixing test before it is locked in. The cheapest high-value sequence is the P0 set: type split, sentence case, tonal grouping, inline errors and 48dp targets. Ship it as one batch, because together these changes alter how the app reads more than any later work on color or motion.
